The structure of the cash application skill, and what it does

The skill was one 909-line file. On main it is now a 155-line card and seven reference files. Commit b2f0563 made the split on 25 October 2026, and pull request #1 merged it on 26 October 2026. A bookkeeping-audit commit, 38aef1c, then changed the method on 27 October 2026. Two things set this skill apart. The payer name on a bank line is often a bank string. And no accounting system holds the remittance that says which invoices a payment settles. And the skill writes nothing: every application and every entry is a proposal that a person posts. This page shows how the files connect, the run stage by stage, and the source behind each step. It also shows the audit: four fixes on main and nine open findings.

C1. The tolerance test runs before the reason table

Step 3 tests the residual against the tolerance first. So an unauthorised deduction inside a generous tolerance becomes a proposed small-balance adjustment, not a collections item. In the worked example, Crestline takes a 2% discount 127 days after the window closed. With a $5 tolerance its 128.00 stays open for collections. With a tolerance of 150, the same 128.00 becomes an adjustment.

C2. Three choices that the skill leaves open

The skill does not say if the tolerance applies per payment or per invoice. The 0.85 threshold names no similarity measure.
