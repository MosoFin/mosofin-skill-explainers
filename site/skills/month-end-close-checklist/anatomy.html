The structure of the month-end close checklist skill, and what it does

On main the skill is a 158-line card and seven reference files. Before the split it was one 991-line file, and the split kept the original text. A bookkeeping audit then changed the method on main. Two things set this skill apart. It is the hub of the close: its task list names 15 other skills in the library. And it observes and reports only: it locks no period, posts no entry and marks no task complete. This page shows how the files connect, the run stage by stage, and the source behind each step. It also shows the audit findings: four fixed on main, one that main never needed, and two open observations.

Audit → findings

Four findings fixed on main, one that main never needed, and two open observations

High · fixed

The continuity check could never break

F4. Step 6 compared this period's opening balance with last period's closing balance, both read live from the same ledger. Live, the opening balance is the prior closing balance, so the two reads always agreed. Now the check compares last month's trial balance as reported with a fresh read of the same date, account by account. Without the reported trial balance, the result is "not performed", never a pass. The first month of a fiscal year expects a break on the P&L lines and retained earnings.

Nine more findings from the bookkeeping audit

F5. The same commit fixed nine more findings. [gated] now means only that a tool needs approval, and a task that is partly observable carries "mixed" with a verdict for each part. Intake question J asks for the cash or accrual basis. Day 3 checks the reversal of last month's accruals, and Day 4 checks clearing and suspense accounts. Each task records a reviewer and a review date. An owner agrees the inventory cutoff to receiving and shipping records by hand. The variance tracker has a prior-period column.
