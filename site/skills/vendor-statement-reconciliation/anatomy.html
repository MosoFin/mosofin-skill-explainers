The structure of the vendor statement reconciliation, and what it does

The card format is on main of MosoFin/mosofin-finance-skills, merged in PR #1 on 26 October 2026, with a bookkeeping-audit fix on 27 October 2026. On main the skill is a 158-line card and six reference files. The split kept the original text of the 730-line file. Two things set this skill apart. The supplier's statement never comes from the books, so the skill always asks for it. And the skill names no QuickBooks tool, so Gate 2 reads the tool names from the catalogue on each run. This page shows how the files connect, the run step by step, and the source behind each step. It also shows the three earlier audit findings, all fixed on main, and two small open points.

Audit → findings

Three findings, all fixed on main, and two small open points

Medium · fixed

733 lines in one file, against a 500-line guide

The file had 733 lines, and the cross-reference fix brought it to 730. Commit 273bb88 split it into a 155-line card and six reference files. The bookkeeping-audit fix a31eacd brought the card to 158 lines. The card holds the six rules that never bend, the seven intake questions, the upload checklist and six stages. The original text moved unchanged into references/. 462 of the 464 non-empty lines are present byte for byte. The other two lines are the description and the onboarding link. The description is now 1,024 characters, which is exactly the limit.

“Keep SKILL.md body under 500 lines for optimal performance.”Anthropic · Skill authoring best practices
SKILL.md + references/ · fixed on main in 273bb88
Low · fixed

Cross-references pointed at skills that are not in the library

Eight sentences named skills that are not in the library: segment-reporting, quickbooks-ar-aging-collections, statement-of-equity-changes, internal-audit-workpaper, sox-controls-design-and-testing, vendor-onboarding-and-w9-tin, vat-gst-international, multicurrency-fx-revaluation. Five rows of the Related skills table did the same, one of them with accounts-payable-automation. A table row and one sentence used a wrong name, accruals-and-prepayments. The library's skill is accruals-and-deferrals. On main, each sentence stands without the name, and the table lists only skills in the library. One sentence under the table names the kinds of skill that are still queued.

“Keep references one level deep from SKILL.md.”Anthropic · Skill authoring best practices
overview.md, gates.md Gate 1, method.md Steps 1, 3 and 5, edge-cases.md · fixed on main in 347fde2
Medium · fixed

Step 0 ranked "vendors never reconciled" as [auto], but no ledger holds that fact

No ledger records which statements somebody reconciled. On main, Step 0 says that the reconciliation history comes from saved runs or from the user. On a first run, the skill asks when each top-ranked vendor was last reconciled. Where nobody gives a date, it reports "not known". It never infers "never reconciled" from the ledger.

method.md · Step 0 · fixed on main in a31eacd
Low · open

Step 0 still says the workspace produces the ranking exactly

Step 0 has the label [auto], and it says the workspace "can produce exactly" the ranking. After a31eacd, one of the seven signals, the last-reconciled date, comes from saved runs or from the user. So the label says more than the step does on a first run.

Suggested: mark the last-reconciled signal [manual] on a first run, as the step text already does in words.

method.md · Step 0 · open on main
Low · open

The Inputs table did not follow the new upload checklist

The Inputs table in method.md still names "AP ageing / vendor ledger" as the required ledger input. The card's upload checklist now says that an ageing alone is not enough. It also asks for a vendor list or a bill search. The Cutoff date row keeps the verdict "Split", but its source cell now says that the user states the period end.

Suggested: make the Inputs table agree with the card's upload checklist.

method.md · Inputs · open on main

The bookkeeping-audit commit a31eacd made more changes that the pages now follow. The skill reconciles at the statement date and lists each ledger item between the two dates. It agrees the AP subledger to the GL, and it checks that the statement adds up. It rolls a balance-forward statement forward. It finds short payments and charges. It drafts entries by case. The overpayment signal is now a debit balance in your own AP. In your AP a credit balance is normal, so a debit balance means you paid too much. The earlier wording, "a supplier account in credit", described the balance as the supplier's statement shows it.
