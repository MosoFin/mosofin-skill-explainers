The structure of the accruals and deferrals skill, and what it does

The skill was one 999-line file. On main it is now a 159-line card and seven reference files. Pull request #1 merged them on 26 October 2026. A bookkeeping-audit commit, c2daadb, then changed the method on 27 October 2026. Two things set this skill apart. Its roll-forward keeps reversing accruals apart from cumulative accruals, so a bonus balance that grows each month gets no flag. And it asks for each input that no ledger holds, such as the bonus estimate, the loan terms and the service periods. It posts nothing. This page shows how the files connect, the run stage by stage, and the source behind each step. It also shows the audit: three changes fixed on main, two checks that main passes, four open findings and five open observations.

The bookkeeping audit changed how the run works

F3. An independent bookkeeper audit raised findings. Its commit, c2daadb, reports 12 fixed, 0 partly fixed and 0 rejected. The roll-forward now keeps reversing accruals apart from cumulative accruals, so a bonus, PTO or interest balance that grows by design gets no flag. Opening balances now agree to last period's schedule. The bonus uses the best-estimate payout × months elapsed, with no discount for probability. Vacation uses the unused balance. Partial pay periods and tax accruals got a basis. Deferred revenue is now a reclass of a receipt in the books. Reversals follow the stated policy. The template got a payroll-tax line.
