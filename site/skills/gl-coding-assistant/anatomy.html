The structure of the GL coding assistant skill, and what it does

The skill was one 983-line file. On main it is now a 159-line card and seven reference files, with 1,229 lines in all. Pull request #1 merged the card format on 26 October 2026. A bookkeeping-audit commit, 7109642, then changed the card and the method on 27 October 2026. The skill suggests an account for each transaction from the entity's own chart and coding history. It posts nothing. It reports history as practice, with its count, and never as proof. This page shows how the files connect, the run stage by stage, the evidence tools by step and the source behind each step. It also gives the audit for the skill owner: one check that passed, nine open findings and two open observations.

A house rule can name an account that history never used

Observation · open

"One account dominates" has no definition

Tier 1 calls a history consistent when "one account dominates", and gives no share or count for it. The learn calculator uses a stricter reading of its own: one account has every earlier payment. Under that reading, a history of 23 of 24 is inconsistent. The skill can call it consistent. The learn page states this difference.
