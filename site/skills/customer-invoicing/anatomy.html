The structure of the customer invoicing skill, and what it does

On main the skill is one 899-line file. The rewrite described here turns it into a 128-line card and seven reference files, and it keeps the original text. Two things set this skill apart. It has two modes: it prepares new invoices, or it checks invoices that you already issued. And it creates, numbers, sends and posts nothing, so every invoice and every entry is a draft. This page shows how the files connect, the run stage by stage, and the source behind each step. It also shows the five audit findings, four fixed and one open.

The audit checked the five sources on 27 Oct 2026 through search results. Nobody opened the pages. Sources 1, 3 and 5 are UK. Source 2 is EU. Source 4 is US. Some items have no outside authority behind them. They are the six stages, the prepare and validate modes, the price check against the standard price and the customer's history, and every example figure. The worked example uses made-up figures. The public pages present these as the skill's rules or as the example's choices. Ask your accountant what applies to you.

Two tool names use a different verb

F4. The tool table names read_item and read_invoice. The other tools that fetch one record use get_, for example get_customer, get_term, get_account and get_estimate. The rewrite did not change them, because the moved text stays byte-identical. Only a live catalogue read can show the real names. Gate 2 already tells the agent to read each name from the catalogue.
