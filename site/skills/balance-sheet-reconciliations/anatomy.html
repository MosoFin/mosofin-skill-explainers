The structure of the balance sheet reconciliations skill, and what it does

On main, the skill is a 161-line card and seven reference files. Pull request #1 merged the card format on 26 October 2026. A bookkeeping-audit commit, ad37a25, then changed the method on 27 October 2026. The skill gives each account a verdict on two sides: the GL side and the support side. An account without independent support is not reconciled. The skill posts nothing. This page shows how the files connect, the run stage by stage, the tool that each step names, and the source behind each step. It also shows the audit for the skill owner: one check passed and seven open findings.

A3. Gate 3 points to the wrong step for one check

Gate 3 says that the carry-forward check is "in Step 8". Step 8 Section 6 holds the carry-forward table. But the opening check, which compares the opening balance with the prior rec, is in Step 6. The pointer is right for one check only. This is a small problem.

A4. Only the Mosofin path asks for the write-off limit

The card asks for the approved write-off limit and its P&L account on the Mosofin path only. The Gate 3 table and the upload checklist do not ask for them. Step 5 needs both on each path.

SKILL.md · Mosofin path and upload checklist · references/gates.md · Gate 3 · open
Medium · open

A5. The status list has gaps

No status value fits an A/R or A/P account with the same-system tie done and the independent test not yet done. The list also does not say if an account is "Reconciled" when permanent items with proposed entries explain each difference. The worked example uses "Reconciled" for prepaid and accrued expenses. That is our reading. The status is true only after a person posts the proposed entries. Until then, the books do not agree with the support.

A6. "Older than 3 months" has no unit

Step 7 says "Items aged > 3 months should escalate". It does not say days or calendar months. In the worked example, a 410 clearing line is 92 days old at 30 September. That is exactly three calendar months, so the line is at the limit.

A7. The read-back says "all" but names six kinds of support

But the read-back example says "all balance sheet accounts" and names only six kinds of support. The worked example names seven accounts. That is the example's choice.

History: the bookkeeping audit changed the method

The commit ad37a25 reports 7 fixed, 0 partly fixed and 0 rejected. An A/R or A/P aging tie from the same books is now a mechanical check, not independent support. The skill tests a clearing account as "zero, every line explained". A write-off goes to a P&L account below an approved limit, never to a suspense account. The commit added the opening check and the dates for sign-off.
